# Kairmel installed Windows and Android acceptance supplement

Reviewed 2026-10-13. This is an evidence checklist for the existing hosted Kairmel shell, not a new native architecture or a release acceptance pass.

## Reuse and current basis

Reuse [NATIVE-GOOGLE-AUTH.md](../../apps/kairmel-shell/NATIVE-GOOGLE-AUTH.md) and the [Kairmel server implementation contract](https://github.com/Yaatal-labs/kairmel-platform/blob/1fa2ef1/docs/native-google-auth-contract.md) for the Google flow, paths, PKCE constants and TTLs. Do not copy or fork those contracts here. Reuse [Android verification](../../apps/kairmel-shell/ANDROID-VERIFICATION.md) for platform build/device results and [merchant navigation](../../apps/kairmel-shell/NATIVE-MERCHANT-WORKSPACE.md) for this branch's eight shortcut paths and tests. Earlier [UXR-06](../scopes/UXR-06-UNIFIED-ACCEPTANCE.md) and the [React desktop plan](../plans/2026-09-10-unified-ui-execution-plan.md) cover the local Studio/BOBO shell, not this hosted Kairmel installer.

Source baseline: Yaatal-OS `a002ff1`, `apps/kairmel-shell/src-tauri/src/{lib,native_auth,kairmel,config,reachability,menu}.rs`, `capabilities/main.json`, `tauri.conf.json`, `tauri.android.conf.json`, `gen/android/app/src/main/AndroidManifest.xml`, `gen/android/app/src/main/java/com/kairmel/app/MainActivity.kt`, and `src/offline.mjs`. Server baseline: Kairmel PR #37 `1fa2ef1`, `worker/api/routes/authRoutes.ts`, `worker/api/controllers/auth/controller.ts`, `worker/database/services/AuthService.ts`, `worker/utils/nativeAuth.ts`, plus native controller/service tests. [Shell wiring](https://github.com/Yaatal-labs/Yaatal-OS/blob/a002ff1/apps/kairmel-shell/src-tauri/src/lib.rs) and [server routes](https://github.com/Yaatal-labs/kairmel-platform/blob/1fa2ef1/worker/api/routes/authRoutes.ts) are source evidence.

The shell uses one hosted WebView, starts at configured Créer (`/` by default), allows Kairmel and Marché origins, and grants the remote page no Tauri IPC permissions. Native Google handoff code exists on both sides. A README sentence saying that the handoff is absent is stale. Windows version is 0.1.1, installer unsigned, with no auto-updater. Android release signing is conditional on external keystore configuration; the reported test APK uses a test key and does not qualify as a production signing identity. iOS, macOS and Linux have no qualified release evidence in this scope.

A public provider response recorded during the parent review on 2026-10-13 returned Google/GitHub/Cloudflare/WhatsApp false and email true. This is a configuration observation supplied by that review, not a fresh provider probe performed for this supplement. Google/WhatsApp acceptance against that configuration is blocked even though code exists. Do not probe a private VPS or modify credentials to make this table pass.

## Required installed acceptance evidence

All rows require actual installed application evidence unless explicitly called a source check. Record artifact checksum/version, OS/device/WebView version, server revision, configured origins, test time and pass/fail/blocker. Source unit tests and a browser harness cannot replace installed evidence. Do not capture credentials, OTPs, callback codes/verifiers or buyer contacts in screenshots or logs.

## Completion rule

An installed acceptance run must distinguish source tests, build success, device pass, blocked provider configuration and untested scenarios. Failed/blocked online payment and settlement are launch blockers even if COD works. Real microphone/camera, Google, browser payment return and release signing require their own evidence. Additional desktop platforms and iOS need separate builds and acceptance rather than a generic Tauri support claim.

Implement only a demonstrated shell/platform delta after the existing tests and device run identify it. Keep checkout, settlement, merchant authorization and AI-credit business logic in Kairmel/Engine/gateway. Use the [headless service supplement](kairmel-headless-os.md) for those boundaries.
