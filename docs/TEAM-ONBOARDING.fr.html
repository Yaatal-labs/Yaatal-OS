02 · La Décision

Pourquoi on a basculé

PowerSync nous donnait du sync SQLite hors ligne. Ça marchait, mais chaque téléphone possédait sa propre copie de la vérité. Quand l'IA a commencé à générer des descriptions de produits et des réponses marchands, on n'avait aucune porte de contrôle pour relire ce contenu avant qu'il soit en ligne. Un prix halluciné pouvait atteindre les clients sans que personne ne vérifie.

Le Engine est maintenant la seule source de vérité. L'app propose des intentions ; le Engine décide de les accepter, les refuser, ou les envoyer en contrôle. Ça nous donne :

Le contrôle

On voit chaque écriture avant qu'elle devienne canonique.

L'auditabilité

Le contenu généré par IA est automatiquement signalé pour relecture.

La souveraineté

Nos données vivent dans notre Postgres, pas dans un service de sync tiers.

Au Sénégal, le signal tombe et la bande passante coûte cher. L'app garde toujours une file locale d'actions et les envoie dès que le signal revient — mais le Engine valide chacune avant qu'elle ne soit publique. C'est du hors ligne maîtrisé, pas du hors ligne naïf.

03 · Règles

Cinq règles — pas d'exception

  1. Parle au Engine, pas à Supabase. Si tu te retrouves à importer @supabase/supabase-js dans du nouveau code, arrête. Utilise packages/core/src/services/engine.client.ts.
  2. Ne ramène pas PowerSync. Il est conservé pour le retour en arrière uniquement. Si tu as besoin d'un tampon hors ligne, construis sur IntentQueue (qui arrive), pas PowerSync.
  3. Une seule variable d'env compte. EXPO_PUBLIC_ENGINE_API_URL pointe vers le Engine. Rien d'autre ne compte.
  4. Pas de nouvelles tables Supabase. Si une fonctionnalité a besoin de persistance, il lui faut une migration Engine et un endpoint API.
  5. Protège Standalone. C'est la baseline de secours. Jamais de force-push. Tout nouveau travail part de codex/bobo-engine-netlify-integration.

05 · Travail Quotidien

Comment travailler sur cette branche

Clone, installe, env, type-check, build. Toujours type-check avant de push.

# 1. Clone et branche
git clone https://github.com/MouhamedN96/BOBO-.git
cd BOBO-
git checkout codex/bobo-engine-netlify-integration

# 2. Installe
pnpm install --frozen-lockfile

# 3. Env — seule celle-là compte
EXPO_PUBLIC_ENGINE_API_URL=https://engine.njooba.com

# 4. Type-check et build
pnpm --filter bobo-app type-check
pnpm --filter bobo-app build

# 5. Serveur de dev
pnpm --filter bobo-app start

# 6. Vérifie le bundle web
pnpm build
rg -n "import\.meta" bobo-app/dist/_expo/static/js/web   # ne doit rien renvoyer
rg -n "yaatal-engine-production" bobo-app/dist/_expo/static/js/web # doit trouver des hits
Ne configure pas de variables mortes. EXPO_PUBLIC_SUPABASE_URL et EXPO_PUBLIC_POWERSYNC_URL sont inactives. Les mettre ne casse rien, mais ça embrouille l'ingénieur suivant qui lit le .env.
06 · Dépannage

Tu bloques ? Vérifie d'abord ici

TypeError: Cannot read 'products'

Le Engine a renvoyé une forme inattendue. Vérifie l'onglet Network, puis mets à jour le mapper dans products.service.engine.ts.

Engine 401

Token expiré. Reconnecte-toi. Le token vit dans authStore et est injecté dans engine.client.ts.

Build échoue : import.meta.env

Import Zustand mal mappé. Vérifie metro.config.js — doit utiliser des points d'entrée CommonJS pour le web.

PowerSync is not initialized

Tu es sur la mauvaise branche, ou un vieux fichier importe encore lib/powersync.
